# Contributing to Wonder Why Kit

Keep the order of priorities: engaging play, visible consequences, then explanation. Follow [brand and voice](docs/BRAND.md): public invitations lead with play, curiosity and joy; concepts and pedagogy support the experience in the background. Prefer small changes with a concrete learning or usability purpose.

1. Describe the observed behaviour and proposed change in an issue or pull request.
2. Edit each world’s `index.html`, stylesheet and `src/` files.
3. Run `npm ci`, `npm run format`, `npm run check`, `npm run build`.
4. Review the rendered result at desktop and mobile sizes. Include before/after images for visual changes, without personal information.
5. Explain what changed, what was checked and any known limits. For simulation changes, update tutor notes and meaningful behavioural tests.

Use original or properly licensed assets and record attribution. Do not add analytics, accounts or external embeds as incidental dependencies. New worlds need a stable slug, catalogue entry, tutor guide and a video plan.

Public contribution/reuse terms remain pending selection of the project licence.
